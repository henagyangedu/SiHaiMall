# 国内上线前清单

整理于 2026-10-10，对应 master `67526d4`。这份清单只讲“离国内上线还差什么”，功能本身的规则在根目录 `CLAUDE.md`。

现状一句话：功能代码写完了，自动化测试都过（后端 301 个测试、十六套点击流程 151 步），但**所有第三方对接都没有用真实账号验证过**，开发库里连一个支付渠道都没有启用。上线前的工作主要是三件事：你定几个配置、拿真实账号逐个联调、准备上线内容。

## 一、要你先定的（定了才能往下走）

| 事项 | 为什么要先定 | 现在的状态 |
| --- | --- | --- |
| ~~应用时区 `APP_TIMEZONE`~~ | 数据库里的时间按它存；数据统计、每日签到的“一天”按它算。有了真实数据之后不要再改。 | **已定为 `Asia/Shanghai`**（2026-10-10），代码默认值和 `.env.example` 都已改；部署时 `.env` 里照抄即可 |
| **可信代理 `TRUSTED_PROXIES`** | 站点前面有反向代理、负载均衡或 CDN 时必须填，否则所有访客被算成同一个 IP，限流和验证码很快把全站挡住 | 留空（只适合访客直连 Web 服务器） |
| **域名和部署方式** | 前后端同域还是分域，决定 `UPLOADS_URL`、`PAY_RETURN_HOSTS`、`CORS_ALLOWED_ORIGINS`、各前端的 `VITE_API_BASE` 怎么填；`APP_URL` 必须是公网 HTTPS（支付回调地址由它生成） | 本机是开发配置 |
| **图片存哪** | 本地存储简单，但要备份 `public/uploads`；有小程序时图片地址必须是完整的 https 地址。也可以用阿里云 OSS 等 | 本地存储 |
| **先上哪几个端** | H5 和 PC 的页面逻辑都用浏览器实际点过；小程序只做过编译，没有在微信开发者工具或真机里跑过 | —— |
| **发不发邮件** | 邮箱验证码、订单通知的邮件渠道都依赖真实的发信服务（`MAIL_*`） | `MAIL_MAILER=log`，只写日志不发信 |

## 二、要拿真实账号联调的（按建议顺序）

下面每一项的代码都是按官方文档写的，测试用的是模拟应答。“风险”一栏是我认为最可能要调的地方。

### 1. 支付——没有它不能卖东西

| 渠道 | 需要你准备 | 重点验证 | 风险 |
| --- | --- | --- | --- |
| **微信支付** | 商户号、APIv3 密钥、商户私钥和商户证书序列号、微信支付公钥和公钥 ID；H5 / 扫码支付用的 AppID；小程序 AppID / AppSecret；要在微信里的 H5 付款还要公众号 AppID / AppSecret | 小程序 JSAPI、手机浏览器 H5、PC 扫码、微信内 H5 四种各付一笔；回调验签解密；退款和退款回调 | 高。四种场景都没有真实付过。微信内 H5 跳回带 `#` 的地址时 `code` 的位置只在模拟环境里验证过 |
| **支付宝** | 应用 AppID、应用私钥、支付宝公钥（公钥模式） | 手机网站支付、电脑网站支付各付一笔；异步通知验签；退款 | 中。没做证书模式，如果你的应用是证书模式要补 |

上线前还要做的平台侧设置：微信商户平台的“JSAPI 支付授权目录”和“H5 支付域名”，公众号后台的“网页授权域名”，小程序后台的服务器合法域名。

### 2. 短信——手机号注册、短信登录、找回密码

- 对接的是 GM 短信平台（`docs/短信平台接入文档.md`）。开发库里这个驱动是启用状态，但**没有和真实平台联调过**，场景标识也还没和平台确认。
- 重点验证：发验证码、校验验证码、查余额；平台的 IP 白名单。
- 注意：启用短信后，手机号注册必须带验证码，境外手机号不能注册（只能用邮箱）。

### 3. 物流——发货之后的体验

| 功能 | 需要你准备 | 风险 |
| --- | --- | --- |
| **物流查询**（快递100） | customer、授权 key | 中。公司编码和返回格式按公开文档写的 |
| **电子面单**（快递100） | key、secret；每家快递的月结账号、密码、网点、面单模板编号 | 高。各家快递要求的字段不一样，第一次接几乎一定要调参数。没有“测试连接”，验证就是真取一个号。不会自动取消面单 |

电子面单可以晚一点上：不启用时照常手填快递单号发货。

### 4. 小程序

- 需要：小程序 AppID / AppSecret（登录用的和支付用的分别在“应用 → 小程序”和“商城支付 → 微信支付”里填）。
- 要在微信开发者工具和真机里把主流程走一遍：一键登录、浏览、下单、付款、订单、售后、上传图片、打开发票 PDF。
- 小程序后台要配：request、uploadFile、downloadFile 的合法域名。
- 风险高：到现在只验证过“能编译”。

### 5. 邮件

- 配 `MAIL_*` 后验证：邮箱验证码（要先在基础设置里打开“邮箱注册需要验证码”）、订单通知邮件（在“设置 → 消息模板”里按场景打开，默认全关）。
- 国内站不发邮件也能运转：通知默认走站内信。

### 6. AI 翻译（只有做多语言内容时才需要）

- 开发库里启用的是 DeepSeek。通义千问和 Claude 的驱动没有用真实密钥调用过。
- 国内单语言上线可以先不管。

## 三、上线时的配置和操作

服务器和环境变量的逐项说明在 `CLAUDE.md` 的“部署检查清单”，这里只列最容易漏的：

- **定时任务**：服务器上加一条每分钟执行的 `php artisan schedule:run`。不加的话，下面这些都不会发生：未付款订单自动关闭、自动确认收货、支付和退款的补偿查询、佣金结算、到货提醒、群发消息、会员等级刷新、消息清理。**群发消息和到货提醒完全依赖它。**
- **`APP_KEY` 生成后不能再换**：所有第三方密钥都是用它加密存的，换了全部解不开。备份数据库的同时要备份这个值。
- `APP_ENV=production`、`APP_DEBUG=false`。
- 首次部署执行 `db:seed`（创建超级管理员，密码只显示一次），之后每次更新执行 `db:seed --class=MenuSeeder`。
- 缓存、会话、队列现在都用数据库，小流量够用；访问量上来后建议换 Redis（要另外验证）。
- 上线后第一件事：改掉初始管理员密码。

## 四、要准备的内容（后台里填）

开发库里这些现在是空的或者是演示数据：

- **协议**：用户协议、隐私政策、退换货政策、配送政策、分销员协议——5 个全部没填。登录注册页、个人中心和页脚会链接到它们（没填的不显示）。
- **真实商品**：现在是 41 个演示商品（货号以 `DEMO-` 开头，图片是自动生成的占位图）。上线前用 `php artisan mall:demo-import --clear` 清掉。
- **运费**：41 个在售商品都没有绑定运费模板，也就是全部包邮。要收运费就建模板并绑到商品上；没有匹配规则的地区会拒绝下单。
- **客服入口**：在线客服链接和客服电话都没填，买家端现在不显示客服入口。
- 站点 Logo、图标、备案号；首页轮播图（要用右侧有主体、左侧留白、不带字的图）和中部横幅；公告、帮助中心。
- 消息模板的文案（不改就用内置的）；小票抬头和页脚。
- 发票：如果要开，在交易设置里打开，并写好开票说明。

**默认关闭、按需打开的功能**：分销、积分抵扣、消费得积分、注册送积分、每日签到、邮箱验证码、发票、邮件通知。会员等级的自动升级靠成长值，而成长值的三个来源（消费得积分、注册送、签到）默认都关着，不开的话等级只能后台手工改。

## 五、上线前你应该知道的取舍

这些是做的时候定下的规则，不是缺陷，但运营上要心里有数：

- **退款不退券、不追回套餐优惠**：已付款订单退款，用掉的优惠券不退回；套餐里退掉一件，套餐优惠不追回。买家可以凑单后再退掉一部分。
- **开票后再退款不会自动作废发票**，也不提醒，要人工到发票管理里处理。
- **发票文件、买家上传的图片地址都是公开的**（靠随机文件名），知道地址就能打开。
- **填了用户协议或隐私政策后，注册必须勾选同意**（买家可以在“账号与安全”里自己注销账号、导出数据）。上线前要把协议换成正式文本；面向境外买家时在“基础信息”里打开“本地存储告知条”。
- **发票只用于人民币订单**（优惠券和套餐已支持其他币种，按汇率换算）。
- **富文本后端不过滤**：商品详情、文章、协议的内容由前端在显示时过滤。后台账号要管好。
- **换绑没做**：邮箱和手机号各只能绑一次，要改只能后台改。
- 搜索是数据库模糊匹配，不分词；商品上万之后会慢，届时要换搜索引擎。
- 站内信的未读数不是实时推送。

## 六、明确没有做的

国内常见、但这一期没有做的：限时折扣 / 秒杀、满减活动、拼团、新人券和订单完成自动送券、公众号网页授权登录、App、云打印机、在线客服聊天、货到付款、余额支付（会员有余额字段，但下单不能用余额付）、订单拆单、多仓库存。

## 建议的顺序

1. 你定第一部分剩下的 5 件事（时区已定）。
2. 搭一台测试服务器（国内、公网 HTTPS 域名），按部署清单走一遍，定时任务加上。
3. 联调支付：先支付宝（最简单），再微信 PC 扫码和手机 H5，最后小程序和微信内 H5。每种都要付一笔、退一笔。
4. 联调短信、物流查询。
5. 小程序在开发者工具和真机里走主流程。
6. 填协议、换真实商品和图片、配运费。
7. 电子面单、邮件、发票等到业务上需要时再开。

联调时把报错信息或回调日志（后台“订单 → 回调日志”）发给我就行；**密钥不要发在对话里**，直接填到后台配置页。
