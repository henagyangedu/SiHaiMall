# 演示数据：格式与导入

商城的演示数据（分类、品牌、商品、文章、公告、帮助、轮播图）写在一个 JSON 文件里，用一条命令导入。
这份文档说明文件怎么写，最后附一段可以直接交给 Codex 的提示词。

## 怎么用

在 `home/` 目录下执行：

```bash
php artisan mall:demo-import --check     # 只检查，不写入；有问题会逐条列出来
php artisan mall:demo-import             # 导入（会先清掉上一次导入的那一批）
php artisan mall:demo-import --clear     # 只清除，不导入
```

- 默认读 `home/database/demo/pet-smart/data.json`。要读别的文件，把路径跟在命令后面：`php artisan mall:demo-import database/demo/xxx/data.json`。
- 导入走的是后台“新增商品 / 分类 / 文章…”的同一套程序和校验，所以结果和在后台手工录入完全一样，导入后可以在后台继续编辑。
- 清除只删导入的那一批（导入时记了清单），不会碰其他数据。演示商品被人下过单也能清，订单不受影响。
- 图片是自动生成的占位图（纯色底 + 名称）。以后有真实图片，在后台把商品图换掉即可。
- 生产环境执行导入或清除要加 `--force`。

## 文件结构

顶层是一个对象，下面六个数组都可以省略：

```json
{
  "categories": [],
  "brands": [],
  "goods": [],
  "article_categories": [],
  "articles": [],
  "banners": []
}
```

仓库里的 `home/database/demo/pet-smart/data.json` 是一份能直接导入的完整示例，拿不准时以它为准。

### 通用规则

- **多语言字段**写成 `{ "zh-CN": "…", "en": "…" }`。`zh-CN` 是默认语言，**必须填**；`en` 建议都填，不填时英文界面会显示中文。
- **code** 是条目在这个文件里的代号，用来互相引用（商品引用分类、轮播图引用商品）。只用小写字母、数字和连字符，同一类里不能重复。它不会显示给买家。
- **金额**一律写成带两位小数的字符串，如 `"599.00"`，基准币种是人民币。
- **富文本**（商品详情 `description`、文章 `content`）只用这些标签：`p`、`h3`、`ul`、`ol`、`li`、`strong`、`br`。不要写 `img`、`script`、`style` 和行内样式。
- 不要出现真实存在的品牌名、真实的人名、联系方式和网址。

### categories 商品分类

最多三级，下级写在 `children` 里。

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 代号 |
| `name` | 是 | 多语言，不超过 100 字 |
| `children` | 否 | 下级分类，结构相同 |

### brands 品牌

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 代号 |
| `name` | 是 | 多语言，不超过 100 字 |

### goods 商品

商品分两种写法：单规格（只有一个价格和库存）和多规格（比如颜色 × 容量）。

所有商品共有的字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 代号，2–41 个字符 |
| `category` | 是 | 分类的 code。**挂在最末一级分类上** |
| `brand` | 否 | 品牌的 code |
| `title` | 是 | 多语言，不超过 255 字 |
| `subtitle` | 否 | 多语言，一句话卖点，不超过 255 字 |
| `keywords` | 否 | 多语言，逗号分隔 |
| `description` | 否 | 多语言富文本，商品详情 |
| `unit` | 否 | 单位，如 `台`、`个`、`袋` |
| `images` | 否 | 占位图张数，1–9，默认 3 |
| `sales` | 否 | 展示用的销量，整数 |
| `params` | 否 | 规格参数，最多 30 行。每行是 `{ "name": 多语言, "value": 多语言 }`，如名称“粮桶容量”、值“5 升”。数值要和详情文案里写的一致 |
| `related` | 否 | 配套的耗材、配件：写它们的 code，最多 12 个，顺序就是展示顺序。**只在设备上写**，不用在配件上反过来写——配件的详情页会自动显示“适用设备” |

```json
"params": [
  { "name": { "zh-CN": "粮桶容量", "en": "Hopper capacity" }, "value": { "zh-CN": "5 升", "en": "5 L" } },
  { "name": { "zh-CN": "供电", "en": "Power" }, "value": { "zh-CN": "5V 插电", "en": "5V mains" } }
],
"related": ["feeder-bowl-kit"]
```

**单规格**再加这些（直接写在商品上）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `price` | 是 | 售价 |
| `market_price` | 否 | 划线价，应不低于售价 |
| `stock` | 否 | 库存，默认 0 |
| `weight` | 否 | 重量（千克） |
| `prices` | 否 | 其他币种的单独定价，如 `{ "USD": "89.99" }`。不写就按汇率自动折算 |

**多规格**不写上面这几个，改为写 `specs` 和 `skus`：

- `specs`：规格，1–3 个。每个规格有多语言的 `name` 和若干 `values`；每个值有 `key`（小写字母数字，同一商品内不重复）和多语言的 `name`。
- `skus`：每一种组合一条。`values` 按 `specs` 的顺序各取一个值的 `key`；其余字段（`price`、`market_price`、`stock`、`weight`、`prices`）和单规格相同。组合不能重复，不必把所有组合都列出来。

```json
{
  "code": "fountain-2l",
  "category": "fountain",
  "title": { "zh-CN": "无线水泵智能饮水机", "en": "Smart Water Fountain" },
  "specs": [
    { "name": { "zh-CN": "颜色", "en": "Color" }, "values": [
      { "key": "white", "name": { "zh-CN": "奶白", "en": "Cream White" } },
      { "key": "green", "name": { "zh-CN": "薄荷绿", "en": "Mint Green" } } ] }
  ],
  "skus": [
    { "values": ["white"], "price": "199.00", "stock": 150 },
    { "values": ["green"], "price": "199.00", "stock": 80 }
  ]
}
```

### article_categories 文章分类

文章和帮助中心各有自己的一套分类，公告没有分类。

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 代号 |
| `type` | 是 | `article`（资讯文章）或 `help`（帮助中心） |
| `name` | 是 | 多语言 |

### articles 文章、公告、帮助

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 否 | 代号；要被轮播图引用时才需要 |
| `type` | 是 | `article` 资讯、`notice` 公告、`help` 帮助 |
| `category` | 否 | 文章分类的 code（类型要一致；公告不填） |
| `title` | 是 | 多语言，不超过 255 字 |
| `summary` | 否 | 多语言摘要，不超过 500 字 |
| `content` | 是 | 多语言富文本 |
| `author` | 否 | 作者 |
| `is_top` | 否 | `true` 表示置顶 |

### banners 轮播图

| 字段 | 必填 | 说明 |
|---|---|---|
| `position` | 是 | 广告位：`home_banner` 首页轮播、`home_middle` 首页中部、`category_top` 分类页顶部 |
| `title` | 是 | 多语言。占位图上写的就是它，所以写成一句广告语 |
| `link` | 否 | 点了跳到哪：`{ "type": "goods", "value": "商品的 code" }`，`type` 还可以是 `category`、`article`（`value` 是对应的 code）、`url`（`value` 是以 `/` 或 `https://` 开头的地址）、`none` |

## 交给 Codex 的提示词

把下面这段原样发给 Codex（在这个仓库里运行）。数量和品类可以按需要改。

```text
请为一个“宠物智能用品”商城编写演示数据。只改一个文件：home/database/demo/pet-smart/data.json。
不要改任何代码，不要直接写数据库。

先完整阅读 docs/演示数据格式.md，并把现有的 home/database/demo/pet-smart/data.json 当作格式范例。
在现有内容的基础上扩充（现有条目可以保留或改写），目标规模：

- 分类：6 个一级分类，每个下面 2–4 个二级分类。参考方向：智能喂养、智能清洁、智能监控与陪伴、
  智能出行与定位、智能健康监测、智能窝垫与恒温、耗材与配件。
- 品牌：6–8 个虚构品牌，不能和真实品牌重名。
- 设备类商品写 6–10 行规格参数（params），数值必须和详情文案一致；设备的 related 里写上它配套的耗材和配件。
- 商品：40 个左右，各二级分类都要有。其中约三分之一是多规格（颜色、容量、尺寸、套餐等）。
  每个商品都要有中英文的标题、一句话卖点和详情（详情 3–6 段，写具体的参数和使用场景，不要空话）。
  价格符合国内市场行情，都给出人民币售价、划线价和美元单独定价；库存 20–500；销量 0–8000，分布要有高有低。
- 文章：6 篇养宠 / 选购指南，2 条公告，8 条帮助中心（配网、清洁保养、售后政策、物流等），
  帮助和文章各建 2–3 个分类。
- 轮播图：首页轮播 3 张，首页中部 1 张，分类页顶部 1 张，分别链接到商品或分类。

要求：
- 严格遵守格式文档里的通用规则（code 的写法、金额是两位小数的字符串、富文本允许的标签、
  zh-CN 必填且 en 也都填上）。
- 中文文案用自然的电商文案，英文是地道的英文而不是逐字翻译。
- 不出现真实品牌、真实人名、联系方式和外部网址；不写医疗功效之类的夸大宣传。

写完后在 home 目录执行 php artisan mall:demo-import --check，按它列出的问题修改，
直到输出“检查通过，可以导入”为止。不要执行不带 --check 的导入命令。
最后告诉我各类数据各写了多少条。
```

导入由你自己执行：检查通过后运行 `php artisan mall:demo-import`，再到前台和后台看效果。不满意就让 Codex 改文件，然后重新导入（会自动替换上一批）。
