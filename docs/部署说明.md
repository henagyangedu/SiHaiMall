# 部署说明

这份说明讲怎么把商城部署到一台 Linux 服务器上。本地开发环境的搭建见根目录 `README.md` 的“快速开始”。

## 一、整体结构

一共四个部分，一个后端加三个前端：

| 部分 | 目录 | 部署成什么 | 建议的域名（示例） |
| --- | --- | --- | --- |
| 后端接口 | `home/` | PHP 站点 | `api.example.com` |
| 管理后台 | `admin-web/` | 静态网站 | `admin.example.com` |
| PC 网站 | `mall-pc/` | 静态网站 | `www.example.com` |
| 手机 H5 | `mall-uni/` | 静态网站 | `m.example.com` |

也可以全部放在一个域名下（后端用 `/api`、`/admin-api`、`/notify`、`/uploads` 这几个路径，前端各占一个子目录），这样可以省掉跨域配置。下面按分开的域名来讲，同域部署的差别会单独说明。

**全站必须使用 HTTPS。** 支付回调、小程序、Google 登录都要求 HTTPS。

## 二、服务器要求

- PHP 8.4 或更高，扩展：bcmath、openssl、pdo_mysql、mbstring、fileinfo、curl、json、ctype、tokenizer、xml
- Composer 2
- MySQL 8
- Nginx（或其他能做 PHP 站点和静态站点的 Web 服务器）
- Node.js 20 或更高（只在构建前端时需要，可以在别的机器上构建好再上传）

## 三、部署后端

### 1. 取代码、装依赖

```bash
cd /var/www
git clone <仓库地址> mall
cd mall/home
composer install --no-dev --optimize-autoloader
cp .env.example .env
php artisan key:generate
```

> **`APP_KEY` 生成后不能再换。** 后台里填的各种密钥（支付、短信等）是用它加密保存的，换了就全部解不开。请把 `.env` 单独备份。

### 2. 配置 `.env`

| 配置项 | 填什么 |
| --- | --- |
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_URL` | 后端对外的地址，如 `https://api.example.com`。支付回调地址和默认的图片地址都由它生成，必须公网可访问 |
| `DB_*` | MySQL 的地址、库名、账号、密码 |
| `APP_TIMEZONE` | 默认 `Asia/Shanghai`。数据库里的时间按它保存，**有了真实数据之后不要再改** |
| `UPLOADS_URL` | 本地存储的图片地址前缀。前后端同域可填 `/uploads`；有小程序时要填完整地址（如 `https://api.example.com/uploads`），或在后台改用云存储 |
| `CORS_ALLOWED_ORIGINS` | 前端和后端不同域名时，填三个前端的地址，逗号分隔，带 `https://`。同域部署留空 |
| `PAY_RETURN_HOSTS` | 前端和后端不同域名时，填手机端和 PC 端的域名（只写域名，逗号分隔）。不填的话发起支付会被拒绝 |
| `TRUSTED_PROXIES` | 见下面的说明 |
| `ADMIN_INIT_PASSWORD` | 可选。初始管理员的密码；不填则随机生成并在终端显示一次 |
| `MAIL_*` | 要发邮件（邮箱验证码、订单通知）就填真实的发信服务；默认的 `log` 只写日志不发信 |

**关于 `TRUSTED_PROXIES`**：站点前面有反向代理、负载均衡或 CDN 时必须填（代理的 IP 或网段，逗号分隔；服务器不能被直接访问时可以填 `*`）。不填的话，后端看到的访客 IP 全是代理的 IP，接口限流、验证码限制、登录失败锁定会把所有访客算成同一个人，很快就全站提示“操作过于频繁”。访客直连 Web 服务器时留空。

### 3. 建表、建管理员

```bash
php artisan migrate --force
php artisan db:seed --force      # 创建管理员 admin，并同步后台菜单。密码只显示这一次，请记下
php artisan config:cache
php artisan route:cache
```

想先看看效果，可以导入自带的演示数据（宠物智能用品）：

```bash
php artisan mall:demo-import --force    # 导入
php artisan mall:demo-import --clear --force   # 清除，只删导入的那一批
```

### 4. 目录权限

Web 服务器的运行用户（一般是 `www-data` 或 `nginx`）要能写这几个目录：

```bash
chown -R www-data:www-data storage bootstrap/cache public/uploads
```

`public/uploads` 是本地存储的图片所在的地方，**要纳入备份**。

### 5. Nginx

站点根目录指向 `home/public`：

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;
    root /var/www/mall/home/public;
    index index.php;

    # ssl_certificate ...; ssl_certificate_key ...;

    client_max_body_size 10m;   # 上传图片、发票文件用

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }
    # 上传目录里不执行任何脚本
    location ~* ^/uploads/.*\.(php|phtml|phar)$ { deny all; }
    location ~ /\.(?!well-known) { deny all; }
}
```

### 6. 定时任务（必须）

加一条每分钟执行的 cron：

```
* * * * * cd /var/www/mall/home && php artisan schedule:run >> /dev/null 2>&1
```

不加的话，下面这些都不会运行：未支付订单自动关闭、自动确认收货、支付和退款的补偿查询、佣金结算、会员升级、到货提醒、群发消息、汇率自动更新、过期消息清理。

## 四、部署三个前端

### 1. 配置接口地址

每个前端目录下有 `.env.production`，里面的 `VITE_API_BASE` 是接口地址：

- **同域部署**：保持默认（`/admin-api`、`/api`）。
- **分域部署**：写后端的完整地址，如后台填 `https://api.example.com/admin-api`，PC 端和手机端填 `https://api.example.com/api`。
- **小程序**：必须是完整的 HTTPS 地址。

### 2. 构建

```bash
cd admin-web && npm ci && npm run build        # 产物在 admin-web/dist
cd mall-pc   && npm ci && npm run build        # 产物在 mall-pc/dist
cd mall-uni  && npm ci && npm run build:h5     # 产物在 mall-uni/dist/build/h5
```

把各自的产物目录作为静态站点的根目录。

### 3. Nginx

管理后台用的是 history 路由，找不到文件时要回退到 `index.html`：

```nginx
server {
    listen 443 ssl http2;
    server_name admin.example.com;
    root /var/www/mall/admin-web/dist;
    location / { try_files $uri $uri/ /index.html; }
}
```

PC 端和手机端 H5 用的是 hash 路由，普通的静态站点配置即可：

```nginx
server {
    listen 443 ssl http2;
    server_name www.example.com;
    root /var/www/mall/mall-pc/dist;
    location / { try_files $uri $uri/ =404; }
}
```

**同域部署时**，在前端站点里把这几个路径转发给后端：`/api`、`/admin-api`、`/notify`、`/uploads`。

### 4. 微信小程序（可选）

```bash
cd mall-uni && npm run build:mp-weixin   # 产物在 mall-uni/dist/build/mp-weixin
```

用微信开发者工具打开产物目录，填自己的小程序 AppID 后上传。还需要在小程序后台把后端域名加进“request 合法域名”，把图片域名加进“downloadFile 合法域名”。

> 小程序目前只做过编译检查，没有在开发者工具或真机上验证过，首次使用请先完整走一遍主流程。

## 五、上线后在后台要做的事

用 `admin` 和初始密码登录后台，然后：

1. **改掉初始管理员密码。**
2. “设置 → 基础信息”：填站点名称、Logo、图标、客服联系方式。
3. “设置 → 语言管理”“币种与汇率”：启用要用的语言和币种。
4. “设置 → API 配置”：配置并测试要用的支付、短信、物流查询、存储、AI 翻译。密钥在这里填，会加密保存，不要写进代码或 `.env`。
5. “设置 → 运费模板”：至少建一个，并在商品上选用，否则按包邮处理。
6. “设置 → 协议管理”：填用户协议和隐私政策。填了之后注册时会要求勾选同意。
7. 按需开启：分销、积分、优惠券、税费、发票、邮箱验证码（默认都是关的）。

各个第三方服务另外要做的设置：

| 服务 | 要在对方后台做什么 |
| --- | --- |
| 微信支付 | 回调地址是 `{APP_URL}/notify/pay/wechat`；公众号内支付要设置网页授权域名和 JSAPI 支付授权目录 |
| 支付宝 | 异步通知地址是 `{APP_URL}/notify/pay/alipay` |
| Stripe / PayPal | Webhook 地址是 `{APP_URL}/notify/pay/stripe`、`{APP_URL}/notify/pay/paypal` |
| Google 登录 | 在 Google Cloud Console 把 PC 端和手机端的网址加进“已获授权的 JavaScript 来源”；服务器在国内时，后台配置里要填代理 |

## 六、升级

```bash
cd /var/www/mall
git pull
cd home
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan db:seed --class=MenuSeeder --force   # 同步新增的菜单和权限点，不会动已有的数据
php artisan config:cache
php artisan route:cache
```

然后重新构建有改动的前端并替换产物目录。

升级前请先备份数据库和 `public/uploads`。

## 七、备份

需要备份三样东西：

- **数据库**
- **`home/public/uploads`**（使用本地存储时）
- **`home/.env`**（尤其是其中的 `APP_KEY`，丢了的话后台保存的所有密钥都无法解密）

## 八、常见问题

**全站提示“操作过于频繁”**
前面有代理或 CDN 而没有配置 `TRUSTED_PROXIES`，见第三节。

**前端请求被浏览器拦截（跨域错误）**
前后端不同域名而没有配置 `CORS_ALLOWED_ORIGINS`，或者填的地址和浏览器里的不完全一致（协议、域名、端口都要一样）。改完 `.env` 要重新执行 `php artisan config:cache`。

**发起支付时提示“支付完成跳转地址不在允许范围内”**
没有把前端域名填进 `PAY_RETURN_HOSTS`。

**图片显示不出来**
检查 `UPLOADS_URL` 是否正确、`public/uploads` 是否可写；分域部署时图片地址要是完整的后端地址。

**订单一直不自动关闭、佣金不结算、群发消息发不出去**
没有配置第三节第 6 步的定时任务。

**后台新功能的菜单没出现**
升级后没有执行 `php artisan db:seed --class=MenuSeeder --force`。

**改了 `.env` 不生效**
执行过 `config:cache` 之后，每次改 `.env` 都要重新执行一次。
